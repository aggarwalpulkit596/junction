# Iterations

A running log of how Junction changed: what each iteration did, why, and how it was checked.
Each iteration is one or more commits whose message starts with `Iteration N:` (`git log --oneline` shows them).
Add a new section at the bottom for every new iteration.

---

## Iteration 0: the baseline (before multiplayer)

**What existed.** Four single-file games and their tooling:

- `junction.html`: the 2D Europe game (4 players: you + 3 robots), with the rules everything else reuses.
- `junction-saboteur.html`: the 2D game plus a hidden saboteur robot, tasks, meetings and votes.
- `junction3d.html` / `junction3d-saboteur.html`: walk-around 3D versions, generated by `tools3d/build.py` from
  templates plus slices of the 2D rules.
- `promo/`, `promo-saboteur/`, `video/`: trailers and a teaser built from real gameplay.

**Why it was committed first.** So every later change shows up as a clean diff against a known starting point.
Big media (exports, footage, audio, about 1.6 GB) is ignored and can be regenerated.

## Iteration 1: a server that owns the game

**Goal.** Real online play for the 3D game, in two lengths: 5–10 minutes and about 30 minutes, hosted on Cloudflare.

**Decisions and why.**

- **Server-authoritative**: the server shuffles, deals and keeps every hand and ticket secret. A host-in-the-browser
  design would have been less work, but anyone could peek at the deck, and the game would die when the host closes
  the tab.
- **Cloudflare Durable Objects**: one object per room is a natural fit. It holds the room's state, all its WebSockets
  and its timers (alarms) in one place, with no database to run. SQLite-backed objects work on the free plan, and
  hibernating WebSockets mean a room costs nothing while people think.
- **Same rules, one source**: `mp/build.mjs` copies the rules out of `junction.html` (payment, tunnels, robot route
  planning, scoring), exactly like the 3D build does. A rule fix in one place reaches the 2D, 3D and online games.
- **Robots fill every gap**: empty seats, timed-out turns and disconnected players are all handled by the same robot
  brain, which returns *actions* that go through the same validation as a human's.
- **Time is a parameter** (`tick(now)`): the engine never reads the clock itself. The Durable Object passes real time;
  the simulator passes a virtual clock and plays thousands of games in seconds.

**Tuning the two lengths** (`mp/sim.mjs`, human seats modelled at 4–10 s per action):

| Blitz trains | 1 human | 2 humans | 4 humans |
|---|---|---|---|
| 12 | 3.0 min | — | — |
| 14 | 3.5 | 5.6 | 8.8 (clock) |
| **18** | **4.4** | **6.9** | **8.8 (clock)** |

| Classic trains | 1 human | 2 humans | 4 humans |
|---|---|---|---|
| 30 | 8.0 min | 12.3 | 20.5 |
| 36 | 10.0 | 14.9 | 25.4 |
| **40** | **11.1** | **17.6** | **28.8** |
| 45 | 12.1 | 19.0 | 28.9 (clock) |

Chosen: **Blitz = 18 trains, 25 s turns, 8 min clock** and **Classic = 40 trains, 45 s turns, 28 min clock**.
Classic fills ~48 of the 50 routes, so it is the "complete" game.

**Checks.**

- `mp/sim.mjs`: 200 games per mode, no stalls, no refused robot actions, every floating card has a city.
- `mp/timeout-check.mjs`: humans who never act, drop out, come back, or get replaced mid-walk. No stalls, no
  busy-looping alarms. Worst cases: Blitz 9.5 min, Classic 30.5 min.
- A bug this caught: if someone took over a robot while it was walking to a card, its stale plan made the room's
  alarm fire every 20 ms. Fixed by dropping the robot's plan when a human takes the seat back (`handBack`).

## Iteration 2: playing online in Junction 3D

**What you see.**

- Start screen: **Blitz** or **Classic** solo, **Play online**, and **Join with a code** (or **Rejoin room ABCD**).
- Online: type a name, create a room (pick the length) or join with a 4-letter code. Invite links look like
  `…/junction3d.html?room=ABCD`.
- Lobby: the code, a copy/share link, the four seats ("A robot plays here" for empty ones), the length (the host
  picks), and Start for the host.
- In game: the room bar shows the room, whose turn it is with a countdown, the game clock, and six emotes. Emotes pop
  up over your robot for everyone. Other players' robots walk live. Your log reads "You claimed…" while theirs read
  "Ada claimed…".
- Game over: scores, the longest route, everyone's tickets ✓/✗, and "Play again in this room".

**How it fits into the existing 3D code.** Every sync from the server rebuilds the game state `S` from the server's
view, rotated so you are player 0. That keeps the whole existing HUD, minimap, sheets and 3D world unchanged. Your
actions (take a card, claim, keep tickets, tunnel, station) are sent to the server instead of applied locally.
Saboteur 3D is built from the same template but keeps online play switched off (`ONLINE_OK=false`) and keeps its
Quick/Long modes, because the server does not know the saboteur rules yet.

**Checks.**

- `node tools3d/sim.mjs 40 20` (plain 3D, solo) and the same for `junction3d-saboteur.html`: unchanged numbers
  (18.3 and 18.2 rounds, ~4.6 sabotages), no page errors.
- `mp/e2e.mjs` against `wrangler dev`, in real headless Chrome, both lengths. Covers create, invite link, lobby, start,
  hidden hands, a reload mid-game (same seat back), a third player joining mid-game (takes over a robot), a whole game
  (Blitz 16–18 rounds, Classic 41 rounds), both players seeing the same board, final scores, and rematch.
  All checks pass.
- Screenshots at desktop and phone sizes for the lobby and the in-game HUD.

## Iteration 3: docs, GitHub and hosting

- `README.md`, `docs/ONLINE.md` (protocol and internals), this file, `CHANGELOG.md`.
- GitHub Actions: `ci.yml` runs the builds and checks on every push. `deploy.yml` deploys to Cloudflare on pushes to
  `main` once the `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` secrets are set.
- `CLAUDE.md` / `AGENTS.md` describe the online pieces for future work.

## Iteration 4: live on Cloudflare

- Deployed with `npm run deploy` to **https://junction.aggarwalpulkit596.workers.dev**: one Worker with the static
  site and the `Room` Durable Object, on the Workers Free plan.
- Checked by running `mp/e2e.mjs` against the live site at normal robot speed (no `BOT_PACE`). It covered create, join,
  reload, a mid-game join, a whole Blitz game (19 rounds, about 1.5 minutes with instant-acting test players),
  the same board for everyone, and rematch. All checks pass.
- To redeploy: `npm run deploy`, or add the `CLOUDFLARE_API_TOKEN` / `CLOUDFLARE_ACCOUNT_ID` secrets on GitHub so
  every push to `main` deploys.

## Ideas for the next iterations

- Saboteur Express online: a human could be the secret saboteur. The server already hides hands; it would also hide
  the role, run meetings, and collect votes.
- Check that a player is near a floating card or route before accepting the action (positions are cosmetic today).
- Quick chat phrases, spectators, and a "public rooms" list.
- A custom domain and a short invite URL.
